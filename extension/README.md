# Codex Provider Manager

在 VS Code 中管理 Codex 的账号、API、对话、监控和备份。**0.6.0 为 GitHub 预发布版，未上架 Marketplace**，与 OpenAI 官方扩展无隶属关系。

## 安装与首次启用

1. 扩展页右上角 `…` →「从 VSIX 安装」，选择 `codex-provider-manager-0.6.0.vsix`；Remote SSH 安装到服务器端。
2. 等当前 Codex 任务结束，执行「开发人员: 重新加载窗口」。
3. 打开「Codex 管理：打开可视化管理中心」，确认版本、机器和目录正确。
4. 后台版本较旧时，先停止代理、暂停监控及定时备份，再到总览点「升级后台」。供应商、账号和用户服务保留。
5. 在总览「平滑切换」点「启用本机平滑切换」，确认后重新加载窗口；等显示「已启用」，首次设置即完成。

首次打开不会切换账号或发送测试请求。兼容模式需明确启用：它调整本机官方扩展的入口文件，完整保留原程序及备份，不改全局编辑器设置。当前只适配 Linux x64、官方扩展 `26.51007.21434` 的已验证程序；官方升级后需重新检查适配。

## 日常怎么用

| 页面 | 主要操作 |
| --- | --- |
| 总览 | 查看机器、后台、当前配置及平滑切换状态 |
| 供应商 | 保存多个官方账号；添加 API、设置 Key、检查与切换 |
| 对话 | 搜索、项目筛选、多选归档、取消归档和删除 |
| 监控 | 设置检测间隔、生效时段、北京时间或其他时区 |
| 备份与检查 | 完整备份、定时备份、校验和脱敏诊断 |

**官方账号：**「新增官方账号」→取名→「登录」→打开官方授权页面输入验证码→回面板刷新。新增和登录不会改变当前账号。「保存当前官方账号」仅支持文件缓存。已保存不保证令牌仍有效。

**API：**添加基础地址与准确的模型 ID，保存后点「设置」输入 Key。地址填到 `/v1`，不加 `/responses`。配置检查不联网；连接和工具格式测试由你主动确认，可能收费。文字通过不代表工具、图片和长对话均通过。

**切换：**等当前任务结束→在目标卡片点切换→「切换并重新加载」→确认。当前窗口重载一次，新 Codex 等后台备份、切换和核对完成后启动；管理中心自动恢复进度。确认成功与实际账号后，在官方历史列表继续原对话。

不关闭 VS Code，不结束其他窗口或 CLI。其他 Codex 仍在线时会等待，可取消；等待一小时作废。切换期间不要更新官方扩展或另开 Codex。「安排稍后切换」保留当前窗口，等 Codex 自然退出才处理。

**同组 API 自动切换：**设置同组 Key 和相同模型 ID→检测→启动分组代理→按生成说明接入。代理只监听本机，只在明确安全拒绝时尝试备用接口；已经输出、开始工具调用或执行情况未知时不重放。只支持 Responses 流式请求，不转换 Chat Completions，不支持 `previous_response_id`、后台响应、登录或图片生成辅助接口。生成配置中的重试次数保持为 0。

**对话整理：**归档、取消归档和删除前说明已知父子会话影响并完整备份。删除当前记录不会删除旧备份。标题可查看信息和复制 ID；继续聊天请到官方历史列表定位，当前没有直接跳转入口。

**监控和备份：**独立后台继续运行，重载窗口不影响它。默认按北京时间设置生效时段；`0–24` 全天，`22–8` 跨午夜。定时检测可能收费。取消切换或失败后，计划保持暂停，按需手动恢复。

## 出错与撤销

| 现象 | 操作 |
| --- | --- |
| 仍是旧版本 | 确认安装到当前机器，再重新加载窗口 |
| 等待首次重载 | 等任务结束，点「重新加载窗口」完成启用 |
| 启动等待程序需要更新 | 重新启用兼容模式，再重载一次 |
| 官方版本尚未适配 | 不使用重载切换，等待适配或采用稍后切换 |
| 等待其他 Codex | 等其任务结束或取消切换，无需手动结束进程 |
| 备份失败、尚未修改 | 按提示检查磁盘、Python 和记录完整性，再创建新计划 |
| 切换结果未知 | 保留备份，核对账号与对话，不直接重试或覆盖恢复 |
| 启动入口或原程序无法核对 | 停止切换；重新安装官方 Codex 可恢复原程序，不删除 `.codex` |
| 后台版本不匹配 | 暂停计划、停止代理，点「升级后台」 |

撤销：总览→「恢复官方启动入口」→等任务结束→「重新加载窗口」。账号和对话保留。卸载本管理器前先恢复入口；入口副本与后台数据不自动删除。

备份位于 Codex 用户目录旁的 `.codex-provider-manager-backups/`，包括普通、归档对话和数据库，逐文件校验；重复 ID 的不同副本均保留。没有一键覆盖恢复，避免丢失新消息。账号、Key 和配置安全副本单独保存在本机受限目录，不上传供应商。

密钥和登录缓存使用受限文件权限，没有额外加密。日志及诊断不记录 Key、验证码或对话正文；真实代理请求会发送到你启用的供应商。当前配置与旧任务实际接口分开展示，未知时明确标识。

## 开发与验证

源码在 `extension/`，共享逻辑在 `core/`，后台在 `agent/`。需要 Node.js 20+、Python 3.10+；切换还需已安装的 `codex-provider` 会话同步工具。

```bash
npm run check
npm test
npm run test:ui
npm run package
```

设置 `CODEX_TEST_PATH` 和 `CODEX_SYNC_TEST_PATH` 可运行隔离的真实进程测试。`scripts/test-ide-reload.mjs` 另需桌面 VS Code 路径 `CPM_VSCODE_DESKTOP`；它克隆官方扩展并使用临时用户目录及本机模拟接口，验证首次启用、重载切换、对话保留和撤销，不接触真实登录。

当前已通过 79 项自动测试、13 项界面测试及真实隔离 VS Code 生命周期验证。真实服务器启用与账号/API 组合仍需用户验收；暂不开发跨服务器对话迁移。


从源码构建请先 `cd extension && npm ci`；浏览器测试先安装 Chromium。完整步骤见[开发说明](../CONTRIBUTING.md)。
