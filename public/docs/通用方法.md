# VS Code Codex 更换 API 与保留对话

以 DeepRouter 为例：先配置和测试，再备份、切换，最后检查原对话和新对话。以后换中转站，也按这个顺序操作。

下面命令用于 Linux/macOS；通过 Remote SSH 使用 Codex 时，在服务器执行。原生 Windows 的路径和密钥读取方式不同，可用文末提示词让 GPT 按你的环境调整。

## 1. 找到配置，确认接口

在运行 Codex 的机器上打开终端：

```bash
printf '%s\n' "${CODEX_HOME:-$HOME/.codex}"
codex --version
```

记下输出的目录，用 VS Code 打开里面的 `config.toml`。文件不存在可以创建；已有内容时合并修改。SSH 服务器、本机 Windows 和 WSL 的记录可能分开存放，需要分别处理。

向供应商确认三项：**接口地址、可用模型、支持哪种接口**。

| 支持什么 | 怎么接入 Codex |
| --- | --- |
| Responses，通常为 `/v1/responses` | 优先直接使用 |
| Chat Completions，通常为 `/v1/chat/completions` | 先配置经过测试的转换工具，再让 Codex 连接它 |
| 只有旧版 `/v1/completions` | 优先换支持现代接口和工具调用的模型 |

接口不能靠改 URL 互换。下面的直接接入示例使用 `wire_api = "responses"`；不能改成 `chat`。转换工具要确认支持当前系统、远程服务器、流式回复和工具调用，本文未提供转换器。[官方配置](https://learn.chatgpt.com/docs/config-file/config-reference)、[接口差异](https://developers.openai.com/api/docs/guides/migrate-to-responses)

## 2. 保存密钥，添加备用配置

执行下面的命令，在提示处粘贴 **DeepRouter API Key**。输入不显示，按回车完成；已有密钥文件会停止，避免误覆盖。

```bash
python3 - <<'PY'
import getpass, os
from pathlib import Path
os.umask(0o077)
folder = Path(os.environ.get('CODEX_HOME', str(Path.home()/'.codex')))
folder.mkdir(parents=True, exist_ok=True)
target = folder/'deeprouter.key'
if target.exists():
    raise SystemExit('密钥文件已存在，请先确认是否需要轮换。')
key = getpass.getpass('DeepRouter API Key（输入不显示）: ').strip()
if not key or any(c.isspace() for c in key):
    raise SystemExit('密钥为空或含空白，未保存。')
with os.fdopen(os.open(target, os.O_WRONLY|os.O_CREAT|os.O_EXCL, 0o600), 'w') as f:
    f.write(key+'\n')
print('已保存；配置中需要填写的密钥路径：', target)
PY
```

把下面内容合并进 `config.toml`。将密钥路径换成刚才输出的**完整路径**；相同配置项直接修改，不重复添加。最上面的两行放在第一个 `[表名]` 之前。

```toml
model = "gpt-6.1-sol"
model_provider = "openai"

[model_providers.deeprouter]
name = "DeepRouter"
base_url = "https://www.deeprouterai.com/v1"
wire_api = "responses"
supports_websockets = false

[model_providers.deeprouter.auth]
command = "/usr/bin/cat"
args = ["/home/your-user/.codex/deeprouter.key"]
```

此时仍使用官方接口。保留官方登录信息，不把登录文件发给中转站，也不把 Key 发到聊天或 GitHub。更换供应商时，修改地址、密钥和实际可用的模型，不照抄模型名称。[官方认证说明](https://learn.chatgpt.com/docs/auth)

## 3. 安装工具，先测试新接口

安装会话同步工具，查看当前状态。本次使用 Node 24；没有 `node`、`npm` 时，先安装 Node.js 并重新打开终端。

```bash
node --version
npm install -g @dailin521/codex-provider-sync
codex-provider help
codex-provider status
```

核对输出中的会话目录和数据库位置。工具版本不同时，以 `help` 为准。[工具说明](https://github.com/Dailin521/codex-provider-sync)

先用新接口回答短问题，默认配置仍保持官方：

```bash
codex exec --ephemeral --skip-git-repo-check --sandbox read-only \
  --cd /tmp -c 'model_provider="deeprouter"' \
  'Reply with exactly API_OK. Do not use tools.'
```

应正常结束并回答 `API_OK`。再测试能否实际读取文件：

```bash
test_dir="$(mktemp -d)"
printf 'FILE_OK\n' > "$test_dir/marker.txt"
codex exec --ephemeral --skip-git-repo-check --sandbox read-only \
  --cd "$test_dir" -c 'model_provider="deeprouter"' \
  '调用工具读取当前目录的 marker.txt，只回复文件内容，不要修改文件。'
```

应看到读取文件的执行记录，最后回答 `FILE_OK`。两项都通过后再迁移；模型列表和普通回复正常，不代表工具也可用。测试可能产生少量 API 费用。

## 4. 备份，再切换

关闭使用同一会话目录的相关 VS Code 窗口和 Codex 任务。远程用户用独立 SSH 终端继续操作。

下面的命令备份会话和数据库，不复制 Key 或官方登录文件。失败时先处理错误，不继续切换。

```bash
python3 - <<'PY'
import json, os, shutil, sqlite3, subprocess
from datetime import datetime, timezone
from pathlib import Path
os.umask(0o077)
p = subprocess.run(['codex-provider', 'status', '--json'], capture_output=True, text=True, check=True)
report = json.loads(p.stdout)
if not report.get('ok'):
    raise SystemExit('状态检查失败，未备份。')
state = report['result']
source = Path(state['codexHome'])
db = Path(state['stateDbLocation']['path'])
target = Path.home()/'codex-backups'/datetime.now(timezone.utc).strftime('%Y%m%dT%H%M%S.%fZ')
target.mkdir(parents=True)
for name in ['sessions', 'archived_sessions', 'session_index.jsonl']:
    item = source/name
    if item.is_dir():
        shutil.copytree(item, target/name)
    elif item.is_file():
        shutil.copy2(item, target/name)
with sqlite3.connect(db.as_uri()+'?mode=ro', uri=True) as original:
    with sqlite3.connect(target/'state.sqlite') as copy:
        original.backup(copy)
        if copy.execute('PRAGMA integrity_check').fetchone()[0] != 'ok':
            raise SystemExit('数据库校验失败，不要切换。')
print('备份完成：', target)
PY
```

记下备份目录，另存一份私有的 `config.toml` 副本。然后执行目标对应的命令，**每次只选一条**：

```bash
# 切到 DeepRouter
codex-provider switch deeprouter --keep-root-model --keep 10 --json

# 以后切回官方时执行这一条
codex-provider switch openai --keep-root-model --keep 10 --json
```

结果应为 `ok: true`，且没有 `partial`、跳过项或待恢复错误。再运行 `codex-provider status`，确认文件和数据库里的供应商一致，最后重开 VS Code。

这些切换命令不包含前面的完整备份，每次切换前都要先备份。已有自带备份和校验的快捷命令时，可使用经过验证的封装。

## 5. 检查对话有没有保留下来

1. 打开原对话，确认历史消息还在，并询问前面讨论过的事情。
2. 在 API 下新建对话，发送：`请记住口令“青竹-4827”，只回复已记住。`
3. 备份并切回官方，在**这条测试对话**里问：`刚才让你记住的口令是什么？`
4. 应回答 `青竹-4827`。再切回 API，确认切换期间新增的消息也还在。

重点检查原有会话没有缺失，新增会话也能找到。严格验证时，对比前后会话 ID 和消息正文，供应商标记之外不应被改动；不要仅凭总数判断。

本次 DeepRouter 的普通回复、工具调用、原会话继续及 API 新会话切回官方均已验证。其他供应商仍需重测，图片和长对话压缩要另测。

### 归档的对话也要检查

归档会将对话从普通列表收起，保留历史；取消归档后可以重新打开。官方提供对应的归档、取消归档接口。[官方说明](https://learn.chatgpt.com/docs/app-server)

本指南的备份包含 `archived_sessions`，所核对版本的同步工具也处理归档对话。切换供应商后它们应继续保持归档，不会因为同步自动回到普通列表。

验证：新建测试对话并记住口令 → 归档 → 备份并切换供应商 → 确认仍已归档 → 取消归档 → 查看历史并询问口令。API 下新建的对话也按同样流程测试。若界面没有取消归档入口，先核对版本和支持的管理入口，不手动搬文件或改数据库。

2026-10-17 已用虚构数据验证双向切换：归档状态、位置、ID 和正文保持不变；尚未用真实界面完成上述全流程。归档不等于备份，不减少记录占用，也不能解决跨供应商的推理内容兼容问题。删除当前对话不会自动清除旧备份中的副本。

## 6. 常见错误怎么处理

| 遇到什么 | 先怎么做 |
| --- | --- |
| 找不到配置文件 | 确认是服务器还是本机，以及第 1 步输出的目录 |
| 找不到 `codex` | 检查官方扩展是否装在当前机器，找到它实际使用的可执行文件 |
| 修改后没生效 | 检查是否修改了用户目录的文件，再重载对应 VS Code 窗口 |
| 401 / 403 | 检查 Key、账户权限、余额和访问限制 |
| 404 | 核对基础地址是否多了 `/v1`，或误填了 `/responses` 等完整请求路径 |
| `Input must be a list` | 请求内容改成消息列表 |
| `Stream must be set to true` | 使用流式回复，即 `stream: true`；本次 DeepRouter 路由有此要求 |
| 普通回复正常，工具失败 | 检查模型是否支持工具，以及是否需要正确的协议转换工具 |
| 会话不见了 | 运行 `status`，检查目录和供应商；不要删除会话或数据库 |
| 对话还在，但不能继续或压缩 | 切回原供应商；不同后端可能无法读取旧的加密推理内容，备份不能解决这一点 |
| `partial`、数据库忙、文件被占用 | 结束相关任务，保留报错和备份，再检查或重试 |
| 429、超时或 5xx | 检查额度、网络和供应商状态；重试前确认工具是否已经执行 |
| 缺少 `codex-auto-review` 通道 | 修复审批通道、切回官方或正常人工授权；不要关闭审批机制绕过 |

切回官方时同步**当前全部会话**，包括 API 期间新建的对话。不要用旧备份覆盖整个当前目录，否则可能丢掉后来的消息。

## 7. 配置日常备份

把第 4 步的备份过程保存为脚本，设置每日执行并保留最近 30 份；切换前的备份另存。Linux 用 cron 或 systemd，Windows 用任务计划程序，macOS 用 launchd。

先手动执行一次，确认副本能读取、数据库检查通过，再启用定时任务。关闭 VS Code 后也要确认能执行；验证新备份后再清理旧副本。若要防服务器整盘损坏，再加一份受保护的异机备份。

本次服务器每天北京时间 04:00 备份。其他机器先核对时区，不直接照抄定时表达式。
