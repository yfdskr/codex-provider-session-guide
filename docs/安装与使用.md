# 安装与使用

适用于 0.6.0。首次建议用一条不重要的测试对话，确认后再用于日常工作。

## 1. 确认操作的是哪台机器

- 本地窗口管理本地环境；Remote SSH 窗口管理连接的服务器。
- 管理中心左下角显示机器、版本和 Codex 目录。更换机器不会自动带走账号或对话。
- 当前验收平台为 Linux x64。平滑切换仅支持官方扩展 `26.51007.21434` 的已知程序；更高版本不代表兼容。

在目标机器终端检查依赖：

```bash
node --version
python3 --version
codex-provider help
```

需要 Node.js 20+、Python 3.10+。管理后台可使用 VS Code 自带运行程序；终端安装会话同步工具仍需可用的 Node/npm。缺同步工具时，先安装 Node.js，再执行：

```bash
npm install -g @dailin521/codex-provider-sync
codex-provider help
codex-provider status
```

若终端没有 `codex`，官方扩展可能自带程序；管理器会尝试查找，也可在 VS Code 设置 `codexProviderManager.codexPath` 填写实际绝对路径。不要复制别人的服务器路径。

## 2. 安装扩展和后台

1. 下载 [v0.6.0 安装包](https://github.com/yfdskr/codex-provider-session-guide/releases/tag/v0.6.0)。
2. VS Code 扩展页 `…` → **从 VSIX 安装**。SSH 窗口确认安装到服务器。
3. 等任务结束，执行 **开发人员：重新加载窗口**。
4. 命令面板运行 **Codex 管理：打开可视化管理中心**。
5. 总览确认后台运行。需要退出 SSH 后持续运行时，按 [后台验收](后台验收.md) 安装用户服务并检查 Linger。
6. 老版后台需要升级时，先停止代理、暂停监控与定时备份、完成或取消登录，再点击 **升级后台**。

## 3. 首次备份与启用切换

1. **备份与检查** → **立即完整备份**。
2. 等“备份通过”，在新记录上点击 **校验完整性**，应显示“校验通过”。
3. **总览 → 平滑切换 → 启用本机平滑切换**，阅读说明并确认。
4. 等任务结束，点击 **重新加载窗口**；回来后确认显示“已启用”。

这一步调整官方扩展的本机启动入口，保留原文件。版本或哈希不匹配时停止，不强行修改检查规则。需要撤销时使用 **恢复官方启动入口**，再重载。

## 4. 添加官方账号或 API

**官方账号：**供应商 → 新增官方账号 → 取名 → 登录 → 打开官方页面输入临时验证码 → 回面板刷新。也可点击 **保存当前官方账号**；当前版本只支持文件登录缓存。新增账号不会切换正在使用的账号。

**API：**添加 API → 填名称、地址、准确模型 ID → 保存 → 点 **设置**，在隐藏输入框填写 Key。例如 DeepRouter 的基础地址填写到 `/v1`，不再追加 `/responses`；实际地址和模型权限由供应商确认。

依次检查：

1. **检查配置**：只检查本机配置，不收费，不证明服务在线。
2. **检测连接**：测试文字流式，主动确认后发请求，可能收费。
3. **测试工具格式**：检查工具调用返回格式，不执行测试工具；仍需确认，可能收费。

仅支持 Chat Completions 或旧 Completions 的服务暂不能直接接入。文字通过也不能保证长上下文、图片和全部工具兼容。

## 5. 日常切换

1. 等当前 Codex 任务结束，点目标账号/API 卡片上的切换。
2. 核对目标，点 **切换并重新加载**，确认任务结束。
3. 当前窗口重载一次；新 Codex 等待后台备份、切换、检查完成再启动，管理面板自动恢复。
4. 确认成功与实际身份，再到官方 Codex 历史列表继续原对话。

其他 Codex 窗口或 CLI 在线时会等待，不会强杀它们；可以取消。等待一小时过期。切换期间不更新官方扩展或启动未接入的客户端。取消、失败或切换后检查监控与备份是否暂停，按需重新开启。

**往返验收：**在测试对话记住“青松27” → 切 API → 确认旧消息并追加“白云28” → 切回官方 → 确认两个词和全部消息。该真实组合尚未在本项目中完成全部验收，不能只凭切换成功提示判断上下文完整。

## 6. 整理对话

1. **对话 → 刷新目录**，按标题、项目或 ID 搜索。
2. 勾选一条已结束的测试对话，点 **归档**。
3. 查看影响范围；涉及其他重要对话时取消。相关任务结束后确认，程序先完整备份再操作。
4. 到 **已归档** 找到它，勾选后点 **取消归档**。
5. 在 **未归档** 和官方历史列表确认原记录及消息都保留。

删除也会展示影响并备份。删除当前记录不清除旧备份；本版没有直接跳转官方对话的公开入口，点击标题是查看信息。

## 7. 自动备份

**备份与检查 → 定时备份**：间隔填 `24` → 勾选 **启用定时备份** → **保存备份计划**。出现下次备份时间表示已安排，第一份在间隔后生成。

关闭或重载编辑器后后台继续。后台重启重新安排下一轮，不补跑错过的任务；代理运行时跳过本轮并记日志。旧备份不自动删除，注意剩余空间。没有一键覆盖恢复，避免旧记录覆盖新消息。

## 8. 设置监控

**监控 → 连接监控**可先按以下值填写，再保存：

| 字段 | 示例 |
| --- | --- |
| 检测间隔（秒） | 1800，每半小时 |
| 无响应超时（秒） | 60 |
| 连续失败几次后避开 | 3 |
| 多久后再尝试（秒） | 300 |
| 每天开始/结束小时 | 8 / 24 |
| 使用时区 | 北京时间，Asia/Shanghai |

`0–24` 为全天，`22–8` 为跨午夜。保存不发模型请求；点击 **开启监控** 并确认后，周期性向已启用 API 发送测试短句，可能收费。此功能不检查官方账号登录是否有效，也不会单独把官方账号切到 API。

同组备用接口需要另外配置本机代理、完全相同的模型 ID，并按生成说明接入；仅开启监控不等于已接入自动切换。详见 [扩展说明](../extension/README.md)。

## 9. 检查后台是否持续工作

记下监控与定时备份的开关、间隔 → 等任务结束 → **开发人员：重新加载窗口** → 打开管理面板，检查后台运行、设置保留，并在下次检测后查看新记录。

退出 SSH、机器重启后持续运行需 Linux 用户服务和 Linger，不能只凭窗口重载测试判断。机器重启场景仍待验收。

## 10. 卸载与求助

先 **总览 → 恢复官方启动入口 → 重新加载窗口**，确认原生启动，再卸载管理扩展。后台服务、备份和凭据不会自动删除；需要停用时先暂停计划、停止代理，再通过面板移除服务或停止后台。

遇错先看 [常见问题](常见问题.md)。提问附上版本、目标平台、点击步骤和脱敏错误；不提供 Key、登录文件、真实对话或验证码。
