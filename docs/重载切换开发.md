# 切换后只重载窗口

2026-10-26 · 0.6.0，默认不启用本机兼容模式。

已实现：选择账号或 API → 点击切换并重新加载 → 当前窗口重载 → 新 Codex 等待后台完成备份及切换后启动 → 管理中心恢复进度显示。

## 接入方式

官方没有公开的暂停启动命令；[自定义启动程序设置](https://learn.chatgpt.com/docs/ide/settings)属于开发用途，当前版本作用于整个应用，因此不写入服务器路径。

改用本机兼容入口：备份官方 `out/extension.js`，将入口替换为加载等待程序的短代码；完整原程序保留在相同 `out/` 目录下，原有相对依赖继续有效。扩展清单和全局设置保持原样，避免 VS Code 缓存入口路径导致重载不生效。

启用需用户在界面明确选择；撤销时核对哈希、逐字恢复原文件及权限。未知版本、原程序变化、错误目录、旧进程回执均阻止重载切换，不自动套用到新版本。当前只适配 Linux x64 与官方扩展 `26.51007.21434` 的已验证程序。

## 代码入口

- `core/ide-adapter.ts`：兼容检查、安装、恢复和当前窗口的启动确认。
- `agent/ide-bootstrap.ts`：官方扩展激活前等待，完成后加载原程序。
- `core/startup-gate.ts`：串行核对切换状态与启动许可，超时不自动放行。
- `core/switch.ts`、`agent/server.ts`：安排和执行前再次核对入口。
- `extension/src/extension.ts`：启用、撤销、重载及恢复管理面板。

旧窗口与 CLI 仍由进程检查保护，不声称能够接管它们的任务。兼容入口只协调已接入的官方窗口；切换期间不应启动未接入的客户端或更新官方扩展。

## 验证

常规检查在 `extension/`：

```bash
npm run check
CODEX_TEST_PATH=/实际路径/codex CODEX_SYNC_TEST_PATH=/实际路径/codex-provider npm test
npm run test:ui
```

真实 VS Code 生命周期测试：

```bash
CPM_VSCODE_DESKTOP=/桌面版路径/code \
CODEX_TEST_PATH=/实际路径/codex \
CODEX_SYNC_TEST_PATH=/实际路径/codex-provider \
node scripts/test-ide-reload.mjs
```

测试克隆公开的官方扩展，使用临时用户目录、虚构凭据和本机模拟接口。验证首次启用并重载、切换只重载一次、切换期间新 Codex 等待、对话保留、撤销后原生启动；核对清单未改动、原入口逐字恢复。

结果：`extension/artifacts/experiments/reload/real-ide.json`。用户当前窗口的真实账号切换继续按[操作说明](账号与接口操作.md)验收，不以隔离测试代替。
