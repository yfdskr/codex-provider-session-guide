# 本机后台：使用与验收

更新：2026-10-29，北京时间。当前交付版本 0.6.0；下方验证记录保留原验收版本，不能当作所有新场景已通过。账号与切换见[操作说明](账号与接口操作.md)。

## 怎么使用

1. 在服务器端 VS Code 用「从 VSIX 安装」安装从 GitHub Releases 下载的 `codex-provider-manager-0.6.0.vsix`。先停止旧版代理和相关任务，再重载窗口。
2. 打开「Codex 管理：打开可视化管理中心」，确认版本、机器和 Codex 目录。
3. 总览或监控页找到「本机后台」。点「启动后台」，再按需启动代理、监控或定时备份。保存供应商等操作也会启动后台，但不自动启用计划。
4. 关闭窗口后，独立进程继续运行。要保证退出 SSH 后继续，暂停后台计划、停止代理，再点「安装用户服务」。
5. 点「查看后台状态」，检查用户服务与 Linger。若未启用，可在服务器终端执行 `loginctl enable-linger "$USER"`；是否允许由服务器策略决定。未启用或无法确认时，不保证退出 SSH 后常驻。

首次启动不自动发模型请求；后台异常重启后，之前明确开启的计划安排下一轮，不补跑错过的任务。监控仍可能产生费用，需主动确认开启。

## 出错怎么办

| 现象 | 下一步 |
| --- | --- |
| 后台未启动 | 点「启动后台」；失败时在设置检查 `nodePath`，需要 Node.js 20+ |
| 用户服务安装失败 | 先确认 `systemctl --user show --property=Version --value` 可用，再查看后台状态与日志 |
| 后台版本不匹配 | 先停止代理、暂停监控和定时备份，再点击新版面板的「升级后台」；不要手工覆盖运行文件 |
| 其他窗口更新了设置 | 刷新后核对最新值，再重新编辑，不重复提交旧表单 |
| 操作结果未知 | 复制提示中的编号，点「查询操作编号」，并核对实际状态；不直接重试 |
| 原代理端口被占用 | 检查旧进程或占用者；后台不会自动换端口，确认后再处理 |
| 备份失败 | 停止代理、等待其他操作完成，检查磁盘、Python 和会话一致性；保留 `.partial` |

后台状态、凭据与日志默认保存在 `~/.local/share/codex-provider-manager/agents/<目录标识>/`，不依赖源码或旧版扩展安装目录。状态页显示实际位置。

后台目录为 700，文件为 600。Key 使用本机受限文件存储，不宣称额外加密；不要上传该目录。原 SecretStorage 副本保留供回退，默认不读取官方登录文件。0.4.0 仅在明确保存、登录或切换账号时处理，见账号操作说明。

## 对话控制的边界

历史对话继续通过独立管理连接读取和整理，写操作与后台使用同一套文件锁。它不能据此判断其他窗口的全部活动任务，也不会自动授予审批。

真实 Codex 隔离测试确认：一个 App Server 的已加载对话不会自动出现在另一个独立实例中。因此，0.3.0 不提供已有 VS Code 对话的发送、停止或审批接管；未来需连接实际负责执行的实例后再开放。

接口依据：[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。
