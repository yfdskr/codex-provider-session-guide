# 常见问题与恢复

先在总览确认机器、Codex 目录、扩展与后台版本。遇到切换失败，保留备份和任务编号，不反复点击。

| 现象 | 怎么处理 | 如何确认 |
| --- | --- | --- |
| 装了扩展却看不到 | 确认安装到当前 SSH 服务器；命令面板运行“Codex 管理：打开可视化管理中心” | 左下角版本、机器正确 |
| 还是旧版本 | 安装对应 VSIX，等任务结束后重载；后台另点“升级后台” | 扩展和后台均显示 0.6.0 |
| 平滑切换显示版本未适配 | 0.6.0 只适配已知 Linux x64 官方版本，不修改版本号绕过检查；等待适配或采用稍后切换 | 兼容检查通过后再启用 |
| 等待首次重载 | 等任务结束，点“重新加载窗口” | 显示“已启用” |
| 等待程序需要更新 | 在总览重新启用兼容模式，再重载 | 当前窗口启动确认有效 |
| 切换一直等待 | 其他窗口或 CLI 还在线；等任务结束并正常退出，或取消本次切换 | 状态结束，不手动强杀进程 |
| 切换没改配置就失败 | 根据具体阶段检查依赖、权限、空间；修复后创建新计划 | 原计划不重跑，新计划有独立结果 |
| 切换结果未知 | 保留现场，核对账号、对话和备份；可靠确认后才解除新计划阻止 | 不能把“已核对”当作切换成功 |
| 供应商配置检查通过，但请求失败 | 配置检查不联网；分别测试文字和工具格式，核对地址、模型权限、余额 | 对应分项出现成功结果 |
| 提示没有 Key | 先检查配置；若无法沿用已有认证，在供应商卡片“设置”里输入 | Key 不出现在聊天或日志中 |
| 401 / 403 | 检查所选 API 的 Key、账号授权和权限；官方账号在官方流程重新登录 | 手动测试通过，不重复无效请求 |
| 404 / 接口不支持 | 基础地址通常填到 /v1；确认支持 Responses，Chat Completions 不能靠改 URL 转换 | 文字流式、工具格式分别通过 |
| 429 / 503 | 查看供应商限额和服务状态；备用接口仅在已接入代理、满足规则时生效 | 不承诺任意故障都能无缝重放 |
| 超时或断流 | 检查网络与供应商；已输出或执行结果未知时不自动重放 | 不产生重复工具操作 |
| 找不到旧对话 | 核对机器、CODEX_HOME、项目筛选和归档分类，刷新目录 | 对话 ID 与消息正确，勿先覆盖恢复 |
| 备份失败或校验失败 | 查看具体错误、磁盘、Python 与文件权限；保留失败目录和原记录 | 新完整备份及逐文件校验通过 |
| 关闭窗口后计划停止 | 查看后台模式，安装用户服务并检查 Linger | 独立 SSH 重连后仍运行 |
| 账号/API 切换后监控停了 | 切换会暂停计划；确认成功后按需手动开启 | 开关与下次执行时间正确 |
| 撤销后官方扩展异常 | 保留备份，重新安装官方 Codex 扩展恢复其程序，不删除 .codex | 官方原生入口正常启动 |

## 为什么不能保证所有对话都能直接控制

本版读取历史记录，不等于接入了其他窗口正在执行的任务。一个进程可能管理多条对话；有记录也不代表正在运行。当前不提供任意窗口的实时控制、跨机器迁移或一键跳转官方聊天。

## 备份在哪里，如何恢复

会话备份在 Codex 目录旁的 `.codex-provider-manager-backups/`；在备份页用 **复制目录** 获取准确路径。账号、配置与安全副本保存在独立的受限本机目录，不应上传。

先校验备份，再比较备份后新增的对话和消息，确认恢复范围。本版不提供一键覆盖恢复；不要用旧数据库或整个 `.codex` 覆盖当前目录。账号/API 切换也不等于需要恢复旧备份。
